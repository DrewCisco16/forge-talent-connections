# Migration from Night Agent v10 to v11.3

Ordered. Each step names what stops being true. No legacy behaviour is carried forward "for fidelity".

1. Freeze v10. Archive Night_Agent_v9.pdf, Night_Agent_v10.pdf, both v10 workbooks, the ChatGPT v10 workbook and its completion report, under archive/v10/. They are the methodological ancestor and the QA evidence, not operating documents.
2. Adopt NIGHT_AGENT_SPEC.md as the only authority. The v10 rule "the skill file wins over the PDF" is dead. New precedence: spec > DISPATCH.md > PROMPTS/ > SCHEMA.json > TESTS/ > workbooks > skill file.
3. Replace the night-agent skill file. Regenerate it from DISPATCH.md (copy DISPATCH.md into the skill body; the skill adds nothing). Delete the v10 seat table (Opus 5 closer, no reviewer seat) and the v10 prompt reference. Re-run `TESTS/na_check.py --package` after every edit. Confirm the Chrome agent can run `python3 TESTS/na_gate.py` and record sha256 hashes on file writes; if it cannot, the guards and write-once checks degrade and the rehearsal must say so.
4. Retire these v10 rules explicitly (I1 to I11): "no sign other thinkers exist"; "merged-5 and its claims only"; "paste the verifier under section 9"; "three failures in one round"; "feedback window touched by nothing after registry" (handshake is now required and logged); "tick round complete only when all four answered"; "Dispatch runs the matching power block"; "twenty-one prompts"; the HOLD check ambiguity; the incomplete final-write inputs; the unlabelled model and simulation claims.
5. Retire two v10 validity conditions as automatic failures and re-file them as flags: STRUCTURAL_GT_EARNED and EMPTY_OPEN_LIST. They now trigger human review, not invalidation, until 10 to 20 runs show which reading is right.
6. Rename files. thinker-N.md becomes seat-<id>.md with a stamp line; check-N.md becomes stage-NN-<operator>/check.md in the claim record format; feedback/astra.md becomes review/review.md; DELIVERABLE.md gains the 14-section shape and is never edited; the verifier lives in final/verifier.md and the assembled file is new.
7. Add the objective gate. Every run starts with P1_gate.md. Operators may pre-set CLASS in ask.md. Nothing else about the ask page changes.
8. Add the EXECUTOR seat when an EXPERIMENT or HYBRID ask exists. Until an executor is registered, EXPERIMENT asks run as HYBRID-NO-EXEC and say so.
9. Run the watched rehearsal (TESTS/ADVERSARIAL_TESTS.md Layer B, items B1 to B12) before any unattended night. Record p = failed seat replies / attempted.
10. Write architecture/criterion.json before the first paired run. Run paired nights (v10-fixed and adaptive on the same task, same night, alternating order) on DEV tasks to tune, then on HOLDOUT tasks to decide. Eight HOLDOUT pairs is the earliest decision point. Nothing is retired earlier, and nothing is promoted on DEV results.
11. Only after step 10: revise the workbooks from measured data. The workbook is a view of the spec; it never carries a rule the spec does not. Do not make v12 before the paired data exists.

What must never be preserved from v10: an edited proof file, a bare PASSED, an unnamed non-negotiable, a prompt count in prose, a vendor benchmark presented as independent, a rule that contradicts another rule.
12. Pilot integration (v11.2): before the first v11.2 night, write architecture/criterion.json and the gate's SPENDING_PERMISSION and PAYLOAD_AUTHORIZATION; confirm Dispatch writes dispatch.jsonl and capture.jsonl and runs `na_gate.py SEND` before every send; confirm captures come from message boundaries; retire the words STRUCTURAL kill from every file (na_check PKG-DEPRI fails otherwise). The pilot's D-LINEAR, D-LEDGER and D-TWOTRACK alternatives enter the paired comparison as named arms once their definitions are copied from the pilot package.
13. v11.3 (autoresearch pass): P4 MERGE mode now writes a seventh section, OPTIONS STANDING, and the METRICS field structural_kills is renamed deprioritized (P4, SCHEMA stage_record, ledger, architecture_run_line); registry.json seat records carry fresh and prior_history; gate.json OBJECTIVES and experiments/baseline.json carry direction, without which G-9 blocks every KEEP; SCHEMA states gain DIRECT. Guards G-2 to G-9 and G-11 block more than in v11.2 (Section 15 rows), so a Dispatch skill file generated from v11.2 must be regenerated. The three WORKBOOKS PDFs were built from v11.2 prompts and are STALE for P4 until rebuilt with WORKBOOKS/build/ (reportlab and the font folder are required and were not available where v11.3 was produced).
