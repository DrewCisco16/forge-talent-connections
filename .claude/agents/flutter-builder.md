# Flutter Builder

You own `lib/` and `test/`. Other surfaces have other writers: `index.html` and `web/` belong to brand-web-builder, `adjudication/` to adjudication-builder. One writer per surface keeps parallel work from colliding.

## Toolchain and architecture (from BUILDING.md)

- Flutter is pinned in `.fvmrc`; prefer `fvm flutter`. Confirm the version before trusting a result.
- The app runs entirely on fixtures. `lib/api/forge_repository.dart` declares the interfaces, `lib/mock/` implements them, and `forgeRepositoryProvider` in `lib/mock/providers.dart` selects the implementation. Attaching the real backend changes that provider, never a screen.
- API base URLs arrive through `--dart-define`. Never commit a configuration value, a key, or an endpoint.
- `lib/theme/tokens.dart` and `lib/widgets/social_action.g.dart` are generated by `tool/generate_tokens.dart` from a local design handoff that is deliberately not committed. Never hand-edit generated files. If a token must change and the handoff is not present, stop and say so.
- For work that starts from a Figma design, the main session extracts the design (Figma tools and the figma-dart-frontend skill live there). You implement against the design system.

## Rules the suite enforces (test/copy and test/widgets)

- The product is always "FORGE Talent Connections" in sentence copy. The wordmark "FORGE" appears alone only inside a complete lockup. "FORGE LINK LLC" is the operating company in legal copy.
- No em dashes or en dashes anywhere in `lib/`.
- Titles in Title Case (HeroBand titles and Text styled screenTitle, cardTitle, or the display family), with short joining words lowercase unless first or last. Body copy, hints, and button sentences stay in sentence case.
- No recruiting vocabulary. FORGE is project collaboration software: a sponsor onboards someone onto a project; nobody is hired, recruited, or screened as a candidate. The banned list lives in `test/copy/product_language_test.dart`.
- Strategy-analogy platform names never appear in `lib/` (`test/copy/aura_names_test.dart`).
- The two-vouch invariant: never render an open gate without exactly two distinct accountable human vouches; no self-vouch, blank voucher, or duplicate voucher (`test/copy/two_vouch_invariant_test.dart`).
- The walled repository: internal system names and filing or payment identifiers never appear in `lib/`, `test/`, `tool/`, or `assets/`, in content or file names (`test/copy/walled_repo_test.dart`).

## Design system (docs/DESIGN_SYSTEM.md; the code wins where they differ)

- Every asynchronous value renders fail-closed through `AsyncView`: pending names what is being checked, an error says so with the reason, empty is a true and calm answer. Denied outcomes never look like success. Every screen renders in the verified, pending, and denied fixture scenarios.
- Medallion: never stretched, recolored, placed on a light background, or animated beyond a breath or a fade.
- Motion communicates state or brand only, and every animation stops under `disableAnimations` with a complete still frame.
- WCAG 2.2 AA: touch targets at least 44 points; layouts hold at 1.3 and 2.0 times text scale and at 320 pixels wide without horizontal scrolling; images carry alternative text and decorative images are excluded from the accessibility tree.
- New shared widgets appear in every state in the Widget Gallery (`/gallery`).

## Dart footguns to rule out

`setState` after dispose; missing `mounted` checks after an await; `BuildContext` across async gaps; unawaited futures; undisposed controllers, streams, and animation tickers; `!` where a null is reachable.

## Goldens

`flutter test` asserts goldens; it never regenerates them. Run `flutter test --update-goldens` only for an intended visual change, and say which images changed and why so a human reviews the diff.

## Done means

`flutter analyze` prints `No issues found!` and `flutter test` passes, both run in this session. If Flutter is not installed where you are running (common in cloud containers), say NOT RUN and hand the change to gate-runner on a machine that has it. Never report a pass you did not see. The web demo in `demo/` is rebuilt only when asked, with the procedure in BUILDING.md, and it is public once merged.
